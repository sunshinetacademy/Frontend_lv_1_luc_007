0) مراجعة سريعة من المحاضرة السابقة

المحاضرة السابقة تناولت input من الأنواع text وpassword وemail، وكذلك عنصر textarea. النهارده هنوسّع معرفتنا بالنماذج.

تذكير سريع HTML
<label for="email">البريد الإلكتروني</label>
<input type="email" id="email" name="email" required>

<label for="message">رسالتك</label>
<textarea id="message" name="message" rows="4"></textarea>
معلومة مهمة: الـ label يوضح للمستخدم معنى الحقل. والربط باستخدام for مع id يخلي الضغط على اسم الحقل يركز المؤشر داخل المدخل.

1) عنصر form والخصائص action وmethod

عنصر <form> هو الحاوية التي تجمع الحقول والأزرار التي نريد إرسال بياناتها معًا.

أولًا: action

الخاصية action تحدد عنوان الصفحة أو المسار الذي سيستقبل بيانات النموذج عند الإرسال. في موقع حقيقي، يجب أن يكون هناك مسار أو برنامج يستقبل الطلب ويعالج البيانات. كتابة action="#" هنا للتجربة فقط وليست نظام تسجيل حقيقيًا.

ثانيًا: method

القيمةالمعنىمتى نستخدمها؟
getتُضاف القيم عادةً إلى عنوان الصفحة في صورة Query String.بحث، فلترة، بيانات غير حساسة نريد أن يكون لها رابط قابل للمشاركة.
postتُرسل القيم داخل جسم الطلب (Request Body)، لا داخل عنوان الصفحة عادةً.إرسال نماذج التسجيل أو البيانات التي تُنشئ/تغيّر شيئًا على السيرفر، ورفع الملفات.
تنبيه: GET لا يجعل البيانات سرية، وPOST وحده لا يشفّرها. استخدم HTTPS، ولا ترسل كلمات المرور في رابط. كذلك التحقق من HTML مفيد لتجربة المستخدم، لكن السيرفر يجب أن يتحقق من البيانات بنفسه.
مثال أساسي form
<form action="/search" method="get">
  <label for="q">ابحث عن كورس</label>
  <input type="search" id="q" name="q">
  <button type="submit">بحث</button>
</form>

إذا كتبت مثلًا Python Kids وضغطت بحث، قد يصبح الرابط بالشكل التالي:

/search?q=Python+Kids

المتصفح يرمّز المسافات والرموز الخاصة في الرابط. التفاصيل قد تختلف حسب طريقة الترميز.

2) أنواع input الجديدة

نحدد نوع الحقل عن طريق type. اختيار النوع المناسب يغيّر شكل الحقل، لوحة المفاتيح على الموبايل، وبعض قواعد التحقق.

2.1 — color

يعرض أداة لاختيار لون، وتكون قيمة الحقل عادةً كود لون مثل #ffcc00.

القيمة الحالية: #ffc928
الكود type=color
<input type="color" name="favoriteColor" value="#ffc928">

2.2 — file

يسمح للمستخدم باختيار ملف من جهازه. الخاصية accept تساعد في تحديد أنواع الملفات المقترحة، لكنها ليست وسيلة حماية؛ يجب التحقق من الملف على السيرفر.

لم يتم اختيار ملف.

الكود type=file
<form action="/upload" method="post" enctype="multipart/form-data">
  <label for="photo">الصورة</label>
  <input type="file" id="photo" name="photo" accept="image/*" required>
  <button type="submit">رفع الملف</button>
</form>
رفع الملفات يحتاج عادةً method="post" وenctype="multipart/form-data"، بالإضافة إلى وجود مسار على السيرفر يعالج الملف.

2.3 — search

حقل مخصص للبحث. شكله قريب من text، وقد يضيف المتصفح زر مسح أو سلوكًا مناسبًا للبحث.

الكود type=search
<input type="search" name="courseSearch" placeholder="ابحث عن كورس">

2.4 — url

مخصص لإدخال رابط، ويستطيع المتصفح التحقق من أن القيمة تبدو كرابط صالح وفق قواعد النوع. لكنه لا يضمن أن الموقع موجود أو آمن.

الكود type=url
<input type="url" name="portfolio" placeholder="https://example.com">

2.5 — month وtime

month لاختيار شهر وسنة، وtime لاختيار وقت. شكل أداة الاختيار يختلف حسب المتصفح ونظام التشغيل.

الكود month / time
<label for="month">الشهر</label>
<input type="month" id="month" name="month">

<label for="time">الوقت</label>
<input type="time" id="time" name="time">

2.6 — submit وreset، والفرق بين input وbutton

النوع submit يرسل النموذج. أما reset فيعيد عناصر النموذج إلى قيمها الافتراضية التي كانت موجودة في HTML عند تحميل الصفحة؛ لا يعني أنه يمسح قاعدة بيانات.

جرّب الأزرار ولاحظ الفرق.

ثلاثة أنواع للأزرار button types
<input type="submit" value="إرسال">
<input type="reset" value="إعادة ضبط">

<button type="button">زر عادي لا يرسل النموذج</button>
<button type="submit">إرسال النموذج</button>
<button type="reset">إعادة ضبط النموذج</button>
اكتب type صراحةً داخل button. الزر الموجود داخل form إذا لم تحدد نوعه قد يتصرف كزر إرسال.

3) خصائص input المهمة: name وvalue وhidden وmin وmax وstep وrequired

3.1 — name: الاسم الذي تُرسل به البيانات

الخاصية name مهمة جدًا؛ غالبًا هي المفتاح الذي يربط القيمة باسمها عند إرسال النموذج. الحقل الذي لا يملك name لا يُرسل عادةً ضمن بيانات النموذج.

id وname مش نفس الوظيفة مهم
<input id="student-email" name="email" type="email">
  • id: لتعريف العنصر داخل الصفحة، وربطه بالـ label أو استهدافه من CSS وJavaScript.
  • name: اسم الحقل ضمن البيانات المرسلة.
  • value: القيمة الحالية أو الافتراضية للحقل حسب نوعه.

3.2 — value: القيمة التي تُرسل، مش بالضرورة النص الظاهر

في حقل النص، القيمة هي النص المكتوب. في أزرار الاختيار و

جرّب إدخال عمر 25 أو قيمة مثل 1.3 في ساعات التدريب، ثم أرسل نموذجًا يحتوي على الحقل لتلاحظ التحقق.

مثال min / max / step
<input type="number" name="age" min="7" max="18" step="1">
<input type="number" name="hours" min="0.5" max="5" step="0.5">

3.5 — maxlength وminlength (غالبًا المقصود max length وmin length)

تحدد minlength أقل عدد من الحروف، وmaxlength أقصى عدد منها. تُستخدم عادةً مع حقول النصوص. أما min وmax فهما للحدود الرقمية أو الزمنية وغيرها حسب نوع الحقل.

مثال length limits
<input type="text" name="username"
       minlength="3" maxlength="20" required>

3.6 — required

تجعل الحقل مطلوبًا قبل الإرسال، وفق قواعد التحقق في المتصفح. مثلًا، required مع email يتطلب وجود قيمة بصيغة بريد إلكتروني مقبولة.

مثال required
<input type="email" name="email" required>

3.7 — novalidate

عند وضع novalidate على عنصر form، يتجاوز المتصفح التحقق التلقائي المعتاد عند الإرسال. هذا لا يجعل البيانات صحيحة؛ يجب أن يظل السيرفر مسؤولًا عن التحقق.

مثال novalidate
<form action="#" method="get" novalidate>
  <input type="email" name="email" required>
  <button type="submit">إرسال دون تحقق المتصفح</button>
</form>

4) Radio وCheckbox وخصيصة multiple

Radio: اختيار واحد من مجموعة

عشان تعمل مجموعة radio، خلي عناصر الاختيار التي تنتمي لنفس السؤال تشترك في قيمة name. المستخدم يختار اختيارًا واحدًا من المجموعة.

اختار نظام الدراسة:

مثال radio
<label><input type="radio" name="studyMode" value="online"> أونلاين</label>
<label><input type="radio" name="studyMode" value="onsite"> حضوري</label>

Checkbox: اختيار صفر أو أكثر

كل مربع اختيار مستقل. إذا أردت إرسال عدة قيم لنفس الاسم، يمكن استخدام اسم ينتهي بـ [] في كثير من التطبيقات الخلفية، لكن طريقة استقبال القيم تعتمد على التقنية المستخدمة في السيرفر.

اختار التقنيات التي تهمك:

multiple: السماح باختيار أكثر من قيمة

تُستخدم multiple مع select للسماح باختيار عدة خيارات، ومع input type="file" للسماح باختيار عدة ملفات.

أمثلة multiple
<select name="courses" multiple>
  <option value="python">Python</option>
  <option value="web">Web</option>
</select>

<input type="file" name="files" multiple>
في المتصفح، اختيار أكثر من عنصر في القائمة قد يحتاج Ctrl أو Command أو طريقة اختيار متعددة حسب الجهاز. وجود multiple لا يعني أن المستخدم اختار بالفعل أكثر من قيمة.

5) select وoption وoptgroup والاختيار الافتراضي

  • select: ينشئ قائمة اختيارات.
  • option: يمثل اختيارًا داخل القائمة.
  • optgroup: يجمع الاختيارات تحت عنوان فئة.
  • value: القيمة التي تُرسل عند اختيار هذا الخيار.
  • selected: تجعل خيارًا محددًا افتراضيًا.

قيمة الاختيار الحالي: python

مثال select / option / optgroup
<label for="course">الكورس</label>
<select id="course" name="course">
  <option value="">-- اختار كورس --</option>
  <optgroup label="Programming">
    <option value="scratch">Scratch للمبتدئين</option>
    <option value="python" selected>Python Programming</option>
  </optgroup>
  <optgroup label="Web">
    <option value="html-css">HTML &amp; CSS</option>
  </optgroup>
</select>
ركز في الفرق: المستخدم يرى Python Programming، لكن القيمة التي تُرسل هي python بسبب value="python". إذا لم تكتب value في option، يكون النص الموجود داخله هو القيمة الافتراضية غالبًا.

قائمة تسمح بأكثر من اختيار

6) list وdatalist: اقتراحات جاهزة مع إمكانية الكتابة

الخاصية list في عنصر الإدخال تربطه بعنصر datalist له نفس قيمة id. المتصفح يعرض اقتراحات، لكن المستخدم يظل قادرًا عادةً على كتابة قيمة أخرى.

مثال list + datalist
<label for="language">لغة البرمجة</label>
<input type="text" id="language" name="language" list="languages">

<datalist id="languages">
  <option value="Python"></option>
  <option value="JavaScript"></option>
  <option value="C++"></option>
</datalist>
الفرق عن select: القائمة المنسدلة تختار من الخيارات المحددة، أما datalist فهي اقتراحات لحقل إدخال. إذا أردت منع القيم غير الموجودة، ستحتاج إلى تحقق إضافي.

7) من المتصفح: Inspect ثم Network ثم Query String Parameters

دي خطوة عملية مهمة: هنشوف البيانات التي يرسلها النموذج بدل ما نعتمد على التخمين.

  1. افتح الصفحة في المتصفح على الكمبيوتر.
  2. اضغط كليك يمين في الصفحة ثم Inspect، أو اضغط F12، أو Ctrl + Shift + I.
  3. افتح تبويب Network.
  4. فعّل Preserve log إن كان متاحًا، ثم أرسل النموذج التجريبي بالأسفل.
  5. اختار الطلب الجديد الذي ظهر في القائمة، ثم افتح Payload أو Headers حسب المتصفح ونوع الطلب.
  6. مع GET، ابحث عن Query String Parameters. مع POST قد تجد البيانات تحت Form Data أو Request Payload.
قد تختلف أسماء التبويبات قليلًا بين Chrome وEdge وFirefox. وإذا لم يظهر طلب، تأكد أنك أرسلت النموذج فعلًا وأن name موجود للحقول.

جرّب نموذج GET

النموذج التالي يرسل إلى الصفحة نفسها باستخدام GET، حتى تقدر تلاحظ تغيّر الرابط وبيانات الطلب. لا تدخل أي بيانات شخصية أو كلمات مرور في التجربة.

نوع الدراسة:

بعد الإرسال، ابحث في Network عن أسماء مثل studentName وcourse وlevel وstudyMode وformVersion.

إيه اللي بيتبعت وإيه اللي مش بيتبعت؟

  • الحقل يحتاج عادةً إلى name حتى يدخل ضمن بيانات النموذج.
  • الـ value هي القيمة المرسلة؛ النص الظاهر للمستخدم قد يكون مختلفًا.
  • الـ radio غير المختار لا يُرسل. والـ checkbox غير المحدد لا يُرسل.
  • الحقول المعطلة disabled لا تُرسل عادةً. أما readonly فيختلف عنها ويُرسل إذا كان له اسم.
  • حقل hidden يمكن إرساله رغم أنه غير ظاهر.
  • رفع الملفات يحتاج نموذجًا بإعدادات مناسبة وطريقة POST غالبًا.
شكل Query String تقريبي GET
?studentName=Sara&course=Python&level=intermediate&studyMode=online&formVersion=lesson-demo-v1

لاحظ أن هذا المثال توضيحي؛ المسافات والرموز قد يتم ترميزها. لا تعتبر البيانات الموجودة في الرابط سرية، لأنها قد تظهر في سجل المتصفح أو السجلات الأخرى.

8) الرموز الخاصة في HTML: < و> و& وغيرها

بعض الرموز لها معنى خاص داخل HTML. مثلًا < تبدأ وسمًا، و> تنهي اسم الوسم. لو أردنا عرض الرمز نفسه كنص، نستخدم HTML Entities.

الرمز الذي نريد عرضهالكتابة في HTMLالاستخدام
<&lt;أصغر من / بداية وسم عند استخدامه في الكود
>&gt;أكبر من / نهاية وسم عند استخدامه في الكود
&&amp;علامة &
"&quot;علامة الاقتباس المزدوجة
'&apos; أو &#39;علامة الاقتباس المفردة
مسافة غير قابلة للكسر&nbsp;مسافة لا ينقسم السطر عندها عادةً
علامة ©&copy;حقوق النشر
مثال عرض كود HTML كنص
<p>اكتب: &lt;h1&gt;Hello&lt;/h1&gt;</p>

الناتج الظاهر للمستخدم سيكون: <h1>Hello</h1>

تقدر تستخدم الرموز المسماة أو الرموز الرقمية. والأهم: لو هتعرض كودًا كمثال داخل الصفحة، لازم تتعامل مع علامات أصغر من وأكبر من بطريقة تمنع المتصفح من تفسيرها كوسوم حقيقية.

9) عنصرَا code وpre

code

<code> يوضح أن المحتوى عبارة عن كود برمجي أو تعبير تقني. هو عنصر inline في الوضع الافتراضي؛ يعني لا يبدأ سطرًا جديدًا وحده.

pre

<pre> يعرض المسافات والأسطر كما كُتبت تقريبًا، لذلك يناسب عرض أمثلة الكود متعددة الأسطر. غالبًا نضع code داخل pre عند عرض كتلة كود.

مثال pre + code
<pre>
  <code>
    let score = 10;
    if (score > 5) {
      console.log("Great!");
    }
  </code>
</pre>
قاعدة سهلة: code يحدد أن النص كود، وpre يحافظ على تنسيق الأسطر والمسافات. التنسيق اللوني للكود يحتاج CSS أو أداة إضافية، وليس وظيفة تلقائية لـ code.

10) عناصر نصية مفيدة: q وwbr وbdi

10.1 — q: اقتباس قصير داخل السطر

عنصر <q> يُستخدم للاقتباس القصير داخل فقرة، والمتصفح قد يضيف علامات اقتباس تلقائيًا.

مثال q
<p>شعارنا هو <q>بنحوّل الحلم لكود</q>.</p>

شعار الأكاديمية: بنحوّل الحلم لكود.

10.2 — wbr: مكان محتمل لكسر السطر

عنصر <wbr> يحدد نقطة يمكن للمتصفح أن يكسر عندها السطر إذا احتاج، مثل الروابط أو الكلمات الطويلة. لا يحذف أي جزء من الرابط ولا يقصره؛ هو فقط يساعد في التفاف السطر بصريًا.

مثال wbr
<p>
  https://example.com/very-long-section<wbr>/student-registration<wbr>/frontend
</p>

https://example.com/very-long-section/student-registration/frontend

10.3 — bdi: عزل اتجاه النص

الصفحة هنا عربية واتجاهها من اليمين لليسار. عند إدخال نص بلغة أو اتجاه مختلف، مثل اسم مستخدم إنجليزي أو رابط، قد يختلط ترتيب علامات الترقيم. عنصر <bdi> يعزل اتجاه النص الداخلي عن اتجاه النص المحيط.

مثال bdi
<p>اسم الطالب: <bdi>Moheb_123</bdi></p>
<p>الكورس: <bdi>HTML &amp; CSS</bdi></p>

اسم الطالب: Moheb_123

الكورس: HTML & CSS

طريقة الدراسة *

الموضوعات المهتم بها

قبل استخدام النموذج في موقع حقيقي: لا ترسل بيانات شخصية فعلية إلى هذا المثال. التسجيل الحقيقي يحتاج Backend، والتحقق من المدخلات على السيرفر، وسياسة خصوصية، وHTTPS.

مراجعة سريعة للكود

  • form يجمع الحقول في نموذج واحد.
  • action يحدد وجهة الإرسال.
  • method يحدد طريقة إرسال البيانات.
  • name يحدد اسم كل قيمة ضمن بيانات النموذج.
  • value يحدد القيمة المرسلة أو القيمة الافتراضية.
  • required وmin وmax وstep تساعد في التحقق داخل المتصفح.
  • submit يرسل، وreset يعيد القيم الافتراضية.

12) أسئلة للمراجعة والواجب

أسئلة سريعة

  1. ما الفرق بين action وmethod؟
  2. لماذا نحتاج name حتى تظهر قيمة الحقل ضمن بيانات النموذج؟
  3. ما الفرق بين id وname؟
  4. ما الفرق بين radio وcheckbox؟
  5. ما الفرق بين select وdatalist؟
  6. لو كتبنا <option value="py">Python</option>، ما القيمة التي تُرسل؟
  7. ما الفرق بين min/max وminlength/maxlength؟
  8. أين نجد بيانات نموذج GET في DevTools؟ وما اسم القسم المتوقع؟
  9. ما الفرق بين code وpre؟
  10. هل hidden مكان آمن لتخزين كلمة مرور أو سر؟ ولماذا؟

الواجب العملي

أنشئ ملفًا باسم student-registration.html يحتوي على نموذج تسجيل دورة برمجة، ويجب أن يتضمن:

  • اسم الطالب، البريد الإلكتروني، العمر، شهر البدء والوقت المناسب.
  • اختيار لون، وحقل بحث، وحقل رابط Portfolio.
  • Radio لطريقة الدراسة، وCheckbox لاهتمامات الطالب.
  • Select يحتوي على Option وOptgroup وخيار افتراضي.
  • Datalist لاقتراحات لغات البرمجة.
  • خصائص name وvalue وrequired وmin وmax وstep وminlength وmaxlength.
  • زر Submit وزر Reset.
  • جرّب الإرسال باستخدام GET، وافتح Network، والتقط ملاحظة بأسماء Query String Parameters التي ظهرت.
  • أضف مثالًا يعرض كود HTML باستخدام Entities، ومثالًا لكل من code وpre وq وwbr وbdi.
